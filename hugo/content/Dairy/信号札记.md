## 前言

实在是太喜欢信号与系统了, 信息论的观点是理解知识的本质不可或缺的理论. 其他的介绍见 { 百日杂谈 } 吧. 这里的性质定位上更像是只使用索引的剪贴板. 主要还是使用 tag 的形式联系内容吧, 我觉得缺乏一定内容积累就直接使用塔式结构不太合适.

### 知识管理

zotero connect 抓取 x 的信息不全, AI 获取 metadata 生成 biblatex 效果很好, 希望使用 LangGraph 建立 agent 自动创建信息条目, 观察 zotero api documents 才发现 web api 是底层支持, client libraries 这种 SDK 级别的抽象已经存在, 社区也有 MCP 框架. 这构成了一次完整的开源项目接触经验.

事实上没有那么多知识需要记录? 不过是重复劳动, 建立不全我的认知体系, 提高开源项目能力就好了, 历史比散文重要凝练的多. 同时博客不怎么写绝对不是博客系统不行, 而是我不愿意发布或者是更新, 所以还是先提供内容, 然后再考虑美观程度吧.
